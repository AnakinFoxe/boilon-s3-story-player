## 合同（2026-10-16，做法是用户定的，原记在 BACKLOG）

### 一、清什么

- 对喵喵说「把西游记的进度清掉」「把所有进度都清掉」：清掉一个目录的断点记录，或者整台机器的全部断点记录（插过的别的卡的
  也在内）。某一集单独从头放，照旧用点播「第 N 集」，不用这个。
- **先确认**：工具说明要求喵喵先复述要清什么（目录名，或者「全部进度」），对方说好了才清，因为清掉的进度找不回来。
- **音量和播放模式不算进度**：播放模式（`bl_ai/play_modes`）不动；音量不变。音量本来就和位置存在同一条断点记录里，清掉以后，
  接着放的那个文件马上存一次，音量跟着存回去。

### 二、清了以后放什么

- **清掉的包括正在听的目录**（清全部时总是包括）：喵喵说完这句，对话结束，这个目录从第一个文件的开头放，和点播第 1 集一样。
  同一次对话里还点播了别的、或者让喵喵暂停、关机，就照那个办：点播的照放；暂停就停在第一个文件的开头，顶部短按从那里放；
  关机前存下的是第一个文件的开头。对话被按键或服务器提前结束也一样。
- **清的是别的目录**：对话照常继续，正在听的故事不受影响；以后切到那个目录（目录选择，或点播不给序号）从第一个文件的开头放。
- 不在对话中（服务器直接调用）就立即照办。

### 三、怎么清

- 新工具 `self.story.forget_progress`：`directory` 是目录名，省略时是正在放的目录（这次对话刚点播过，就是点播的那个），和
  `self.story.set_play_mode` 一样；`all` 为 true 时清全部。没有卡、空卡或卡出错时回答没有可播放的卡。
- **喵喵一调用就清，不等对话结束**：播放器先忘掉内存里记着的这些文件的位置；正在听的目录被清时，故事在内存里退到第一个文件的
  开头，等对话结束再放。所以之后任何一次存盘（对话中每 30 秒一次、点播切走前、关机前）都不会再把旧位置存回去。删除交给断点线程，
  排在已经排队的存盘之后。
- **断点表**（NVS `bl_resume/state_v2`）：清一个目录时，删掉这张卡上这个目录的记录，其余照存，只在真删掉了记录时才写；一条
  不剩，或者清全部，就删掉 `state_v2` 这个键，而且先删更早格式的 `state_v1`，否则 v2 没了会退回去读 v1 里的旧位置。**绝不写
  0 条的空表**：v1.3.0 及更早的版本把空表当成损坏，读到它就再也存不了进度，回滚到旧版本也要照常。
- 断点表本身损坏时：清一个目录不动它，记一行错误；清全部照删，这也是修好损坏的表的一个办法。
- 删除完成之前，断点线程对任何文件的位置都回答「还不知道」，播放器像平时等书签一样等它（通常几十毫秒）；续播策略记着的
  「上次已存」作废，下一次内容相同的存盘照样写进去。
- NVS 仍然只在断点线程里写，队列仍是 2 个槽；排不进去（播放器正在切换，或队列满）就下一轮（10 毫秒后）再试，请求不丢。
- 日志：`AI forget directory=… current=… in_chat=…` 与断点线程的 `Forget all=… status=…`。

### 不做

- 不加「看看哪些目录有进度」之类的查询；`self.story.list` 不变。
- 持久格式不变：`state_v2` 照旧，不加新键；清除只删记录或整个键。

### 验收

- 主机：断点表（清一个目录、清到一条不剩、清全部、损坏的表、写失败、只有旧格式时）、NVS 删除的调用、断点线程（删除排在存盘
  之后、删除前位置回答「还不知道」、删除后同样的存盘照写）、播放器（不再存旧位置、从第一个文件的开头放、与暂停／点播／关机
  同时）、喵喵工具的回复；CI 清单全过；对关键逻辑做变异抽查；两个变体用 ESP-IDF 6.1 编译通过，记录大小。
- 设备联调（USB 装测试版 `v1.3.90`，边用边记串口日志）：
  1. 正在听某个目录的中间一个文件时说「把〈这个目录〉的进度清掉」：喵喵先复述、说好以后说完这句结束对话，从第一个文件开头放；
  2. 正在听 A 时说「把〈B〉的进度清掉」：对话继续，结束后 A 照常接着放；再用目录选择切到 B，从第一个文件开头放；
  3. 说「把所有进度都清掉」：正在听的目录从头放；长按关机再开，从刚才那个文件接着放，别的目录都从头；
  4. 音量和播放模式没变；
  5. 日志里看清除和存盘的记录有没有异常，以及内部 SRAM 的最低值（停止线 40 KB，v1.3.0 实测 117,351 bytes）。
- 测试版只把版本名改成 `v1.3.90`，代码与 v1.4.0 相同：SD 卡只装更新的版本，测试版若也叫 v1.4.0，最后发布的 v1.4.0 就装不上。
- 发布后：用户把 Release 里的 v1.4.0 拷到 SD 卡根目录正式升级。
