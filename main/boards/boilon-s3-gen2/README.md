# BOILON S3 Gen2

BOILON S3 二代（ESP32-S3）儿童故事机的非官方固件板型：离线播放 TF 卡里的故事；联网时可以和小智 AI「喵喵」对话。它不能
复用上游的 `jiuchuan-s3`：二代的保电信号是 GPIO15，显示与音频的组合也不同。本项目与 BOILON、九川、乐鑫或小智服务的运营方
没有隶属、授权或背书关系。

## 硬件

以下是开发用的这一台的实测结果。别的批次可能不同，刷机前请先核对。

- 芯片：ESP32-S3（QFN56，revision v0.2），40 MHz 晶振；16 MB Flash（厂商 ID `0x46`，DIO／80 MHz）；芯片内置 8 MB PSRAM。
- 原厂固件：基于小智的 2.0.5（ESP-IDF v5.4.1）。原厂 Bootloader 支持自动回滚；Secure Boot 与 Flash 加密关闭。
- 分区（原厂布局，本固件沿用，见 [`partitions/boilon-s3-gen2.csv`](../../../partitions/boilon-s3-gen2.csv)）：`nvs` 32 KB、
  `otadata` 8 KB、`phy_init` 4 KB、`ota_0` 与 `ota_1` 各 `0x3e0000`、`assets` 8 MB。
- USB：芯片自带的 USB-Serial/JTAG（VID:PID `303A:1001`）。

| 功能 | 引脚 |
| --- | --- |
| 保电（PWR_EN，高电平保持供电） | GPIO15（RTCIO15） |
| 按键：顶部（电源）高有效；中间、底部低有效，内部上拉 | GPIO3；GPIO6、GPIO7 |
| 屏幕 JD9853，SPI，240×296 工作画布（圆角与最底边留内边距） | MOSI 40、SCLK 41、CS 9、DC 39、背光 46 |
| 音频：ES8311（喇叭）与 ES7210（麦克风，I2C 地址 0x41），共用 I2S0 | I2C SDA 1、SCL 2；I2S MCLK 38、BCLK 14、WS 13、DOUT 12、DIN 11 |
| 功放使能 | GPIO42 |
| TF 卡，1 线 SDMMC | CLK 47、CMD 48、D0 21 |
| 电量（分压后的 ADC1 通道 3） | GPIO4 |

ROM 下载模式下没有程序保持 GPIO15，松开电源键就会断电。用 USB 刷机前，先按住顶部键运行
[`scripts/boilon/rom_latch_gpio15.py`](../../../scripts/boilon/rom_latch_gpio15.py)，看到 PASS 再松手。这台机器上 USB 的
`hard_reset` 会停在下载模式；要让它离开，用 esptool 的 `--after watchdog_reset` 关机，再按电源键开机。备份、写入和刷回的
完整步骤见[刷机说明](../../../docs/boilon/FLASHING.md)。

## 两个变体

### AI 变体：`boilon-s3-gen2-ai`

```sh
python3 scripts/build.py boilon-s3-gen2 --name boilon-s3-gen2-ai
```

日常使用的版本。上游小智 `Application` 跑主循环，本板的故事播放器在独立任务里运行（[`m3_ai_main.cc`](m3_ai_main.cc)），播放
功能和按键与离线变体一致（见下文「播放器」）。

联网与激活：

- 没存过 Wi-Fi 时不开 Wi-Fi、不开热点，也不写身份。
- 播放界面同时长按中间和底部约 5 秒，打开临时配网热点 `Boilon-XXXX`（开放热点，10 分钟后自动关闭）。手机连上后打开
  `192.168.4.1`，填入家里的 Wi-Fi。热点只能这样打开，连不上 Wi-Fi 也不会自动打开。
- 存过 Wi-Fi 后，开机约 3 秒在后台连接。需要激活时，屏幕显示 6 位激活码，到 xiaozhi.me 添加设备；激活完成提示「已激活」。
  配网热点打开时显示配网页（热点名、地址和剩余时间）。
- 开机 NVS 初始化失败、身份写不进去，或 NVS 里存有 `wifi/ota_url` 时，一律不联网，只连固件内置的官方地址；配网热点关闭后
  也会再查一次 `wifi/ota_url`。原厂 `assets` 分区不读也不写。
- 开机时 NVS 可用条目少于 126（一页）就把存储当作出错：这次开机不开 Wi-Fi、不开配网热点，故事照常、照常存断点。上游写
  NVS 失败会中止，这样避免联网后反复重启。

网络策略在 [`m3_ai_network.h`](m3_ai_network.h)（主机测试 `test_m3_ai_network`），板级接线在 [`m3_ai_board.cc`](m3_ai_board.cc)。

和喵喵对话：

- 播放界面双击顶部键：上游在待命、Wi-Fi 已连且麦克风可用时，故事让出声音，像唤醒词那样开始对话（响一声提示音后开始听）；
  否则只提示「喵喵暂时不在线」，故事不停。没有唤醒词。
- 麦克风：ES7210 的槽 0 作单声道输入，只在 AI 在听时上电、取消静音并采集，不对话时断电。ES7210 不应答只让 AI 不可用。
- 对话中：中、底短按调音量，长按、组合键和目录无效；顶部短按结束；顶部长按照常关机。屏幕换成 AI 页，喵喵按连接中、我在听、
  想一想、我在说各有动画，说话时按服务器给的情绪换表情，对话因断网、出错或没能开始而结束时显示「出错」脸；打断了正在播的故事
  时底部显示「故事已暂停」。AI 就绪时播放页右上角显示喵喵头像。
- 结束（顶部短按、「回到故事」、服务器结束、断网或出错）后：之前在播，就从约 5 秒前接着播（最多回到本集开头）；之前暂停，
  就保持暂停。服务器结束对话时，已收到的告别语先播完（最多 3 秒）。不是孩子发起的对话会被立即结束；故事若被上游打断，在上游
  回到待命后自动接着播。
- 孩子的话和 AI 的回答只上屏幕、不写日志（上游 `Application` 日志降为 WARN，板级只记情绪词）；麦克风只记录电平汇总。

会话规则在 [`m3_ai_session.h`](m3_ai_session.h)（主机测试 `test_m3_ai_session`）。

喵喵能调用的板级工具（MCP）：

- `self.story.set_screen_style`：对喵喵说「换成夜灯／暖纸」「换成陪听／故事卡」「打开／关掉字幕」，当场切换，重启后回到
  [`p5_1_ui_options.h`](p5_1_ui_options.h) 里的默认组合。字幕打开时，想一想和说话时的气泡显示孩子说的话和喵喵正在说的那一句。
- `self.story.back_to_story`：结束对话，回到故事。
- `self.story.list`：不带参数时列出目录、各目录的文件数和现在选中的那一个；带 `directory` 时分页（每页 20 个）列出这个目录的
  文件和序号；带 `keyword` 时在目录名和文件名里找（英文不分大小写，空格隔开的几个词要全部出现），最多 20 个结果。名字去掉
  扩展名，太长的截到约 20 个汉字，每次回复不超过约 4 KB。
- `self.story.play`：目录名加可选的序号。只给目录，从这个目录的断点接着播；给了序号，从那个文件的开头播。之后照常播完接着播
  下一个，到目录末尾停。目录名先找完全相同的，再找唯一包含它（或被它包含）的；被截短、带「…」的名字也认得。只放卡里的内容，
  不在线点歌；没有卡、空卡或卡出错时回答「没有可播放的卡」。对话中点播时，先等喵喵这次的回答说完再切（请求后 5 秒内没开口、
  或总共等满 20 秒也切）。
- `self.story.set_barge_in`：打开或关掉「回答中插话」，见下文。
- 上游的 `self.audio_speaker.set_volume`（0–100）调音量后，播放器采用新值：屏幕音量跟着变，随下次断点保存。
  `self.get_device_status` 只返回音量和电量（电量未知时不写电量），不报 Wi-Fi 名等其他信息。

点播的查找与回复在 [`m3_ai_library.h`](m3_ai_library.h)（主机测试 `test_m3_ai_library`）。

回声消除与回答中插话：

- 开机自检：功放还关着，给 DAC 送约 0.36 秒 −20 dBFS 的 1 kHz 断续音（喇叭不出声），同时读 ES7210 的四个槽。槽 1、3 中恰好
  一个跟着变（开与关相差至少 30 dB，开时不低于 −60 dBFS）才作播放参考；参考增益让满幅播放不超过约 −6 dBFS。没找到时一切照旧。
- 找到参考后，麦克风输入改为「槽 0 + 参考」两路交给上游音频前端。
- 「回答中插话」默认关，喵喵说话时照旧不开麦。对喵喵说「打开回答中插话」，从下一次对话起，上游用设备端回声消除和 realtime
  听模式，由 xiaozhi.me 判断孩子开口并停下回答；说「关掉插话」从下一次对话起关。开关存在 NVS `bl_ai/barge_in`（1 开、0 关，
  没有或其他值按关），重启后记住；没找到参考时不能打开。只在两次对话之间、上游待命时切换。

规则在 [`m3_ai_echo.h`](m3_ai_echo.h)（主机测试 `test_m3_ai_echo`），自检和两路读数在
[`m2_local_codec.h`](m2_local_codec.h)（主机测试 `test_m2_local_codec`）。

没有卡也能用：没卡、空卡和卡出错（挂载失败、不是 FAT32、扫描出错、播放中出错）共用「没有故事」页，屏幕说明原因；AI 就绪时
双击开始对话；中、底短按调音量；同时长按中间和底部约 5 秒打开配网热点；顶部长按关机。音量从 60 开始（播放中出错时沿用当时
的音量），不保存。不做热插拔：插卡后要重新开机才播放。规则在 [`m3_ai_device.h`](m3_ai_device.h)（主机测试 `test_m3_ai_device`）。

AI 变体另有两处保护：「没有故事」页也按播放器的规则自动关机（对话中、上游在放推送的声音时都不算闲置）；上游连续停在「升级中」
满 60 秒（本固件不接受服务器下发的固件升级，上游失败后不退出这个状态），就像长按一样保存进度并关机。

### 离线变体：`boilon-s3-gen2-local-library`

```sh
python3 scripts/build.py boilon-s3-gen2 --name boilon-s3-gen2-local-library
```

只有故事播放器的后备版本。入口是 [`m2_library_main.cc`](m2_library_main.cc) 里的板级 `app_main`：只编入只播放的
`AudioService`、`LocalMp3Player` 和 `main/media/`，不编入网络、OTA、协议或小智 `Application`，也不启用麦克风。顶部双击只显示
AI 离线提示，不打断播放。它不能从 SD 卡升级，每次都要用 USB 写入。

## 播放器（两个变体共用）

- 媒体：SD 卡 1 线、20 MHz、只读挂载 FAT32；扫描根目录和一级目录，按自然顺序排列，识别 MP3 和 WAV。WAV 由播放器直接读 PCM
  （[`main/media/wav_format.h`](../../media/wav_format.h)）：整数 8–32 位或 32 位浮点、单声道或立体声、8–48 kHz，总时长取自
  文件头，续播和 ±30 秒直接跳到对应位置；其他编码当坏文件跳过。同一目录里两种格式按完整文件名混排。一集播完自动接下一集。
  扫描出的目录表建在 PSRAM 里，卡上文件多也不挤占内部 RAM。
- 显示：240×296 屏幕上的像素界面（[设计记录](../../../docs/boilon/P5_1_PIXEL_UI.md)，每个画面的样子见
  [设计图](../../../docs/boilon/p5_1_gallery/README.md)）：默认暖纸配色和故事卡播放页，显示目录与第几集、曲名、播放状态、
  分段进度条与时间、音量和估算电量；调音量、±30 秒、选择目录和没卡等有各自的画面。画面画在 PSRAM 的索引帧里，只把变化的
  部分送到屏幕（`p5_1_ui_*.h`，主机测试 `test_p5_1_ui` 与原型逐像素比对）。字库外的字显示空方框。
- 断点：最近 32 个文件各自保存位置和音量，存于 NVS（`bl_resume/state_v2`，旧格式 `state_v1` 只读兼容）、跨关机保留、按 LRU
  淘汰；每 30 秒，以及暂停、切曲、切目录和正常关机时保存，开机自动续播。播放时记住最近约 3.5 分钟的帧位置，回退与 ±30 秒跳转
  从附近的帧定位，不再从文件头扫描。
- 音量：0–100，步长 5，每档 2.5 dB；100 为九川 jiuchuan-s3 参考板的最大音量（ES8311 数字音量 −6.5 dB，PCM 不缩放），由
  [`m2_local_policy.h`](m2_local_policy.h) 的 `kDacGainDb` 一个常量决定。
- 故障：某个文件打不开或解码出错，就写一行日志（`Decode failed stage=…` 与 `Trace event=SKIP`）并像播完一样切到下一个。连续
  3 个文件放不出声音时停下：其中有打不开或读不了的（卡的问题，例如拔了卡），按读卡出错处理；只是坏文件，就停在「播放错误」，
  顶部短按从这个文件再试，选目录等照常可用。主循环 30 秒没有进展即断电。
- 自动关机（规则在 [`m5_power_policy.h`](m5_power_policy.h)，主机测试 `test_m5_power_policy`）：估算电量第一次降到 10% 时，
  屏幕下方提示一次「电量低，请充电」约 5 秒；连续 3 次读数（约 15 秒）都不高于 3%，就像长按一样保存进度，显示「电量低」页约
  3 秒后关机。暂停、目录播完或停在没卡页时 3 分钟没按键，也保存进度并关机。电量未知时不动作；测不出是否在充电。电量的估算
  依据见 [M2_BATTERY_BASIS](../../../docs/boilon/M2_BATTERY_BASIS.md)。

| 操作 | 播放器中的行为 |
| --- | --- |
| 顶部短按 | 暂停／继续 |
| 顶部双击 | AI 变体：和喵喵对话；离线变体：显示 AI 离线提示，不打断播放 |
| 顶部长按约 2 秒 | 保存断点后关机 |
| 中间／底部短按 | 音量 +5／−5 |
| 中间长按约 0.8 秒 | 上一首（目录第一个文件上不动作） |
| 底部长按约 0.8 秒 | 下一首 |
| 按住顶部，在关机触发前点中间／底部 | 后退／前进 30 秒，可连点累计 |
| 同时短按中间和底部 | 打开目录选择：中间往上、底部往下，顶部确认，约 5 秒无操作自动取消 |
| 同时长按中间和底部约 5 秒（AI 变体） | 打开配网热点 |

## 版本与 SD 卡升级

两个变体开机都打印版本名（[`m6_release.h`](m6_release.h)，例如 `boilon-ai-player v1.2.0`），「正在检查」页底部也显示版本号。

AI 变体开机挂上 SD 卡后、扫描之前，若卡的根目录有比自己新的 `boilon-ai-player-vX.Y.Z.bin`，就写进另一个 OTA 槽、校验后切换
并重启（规则在 [`m7_sd_update.h`](m7_sd_update.h)，写入在 [`m7_sd_update_esp.h`](m7_sd_update_esp.h)）。屏幕显示「正在升级」、
版本和进度，约半分钟到一分钟；新版本先显示约 3 秒「升级完成 · 现在是 vX.Y.Z」，启动完成后在 `PENDING_VERIFY` 时确认自己。
新版本一开机就崩溃时，原厂 Bootloader 在下次开机退回原来的版本（新槽以 `PENDING_VERIFY` 启动已经实测，退回这一步没有实测）。电量低于 20%、版本不比设备上的新、文件名不对（包括离线变体的
`-offline.bin`）、文件读不出来或不是 app 镜像时不升级，照常开机。这是本板唯一由固件自己写 app 槽和 `otadata` 的路径，上游的
`FIRMWARE_UPGRADE_ENABLED` 仍关闭。

## 构建与刷写护栏

只用 `python3 scripts/build.py boilon-s3-gen2 --name <变体名>` 构建。所有变体都是 app-only：构建脚本只发布 `build/xiaozhi.bin`，
并主动移除陈旧的 `build/merged-binary.bin` 和自动生成的 `*flash*args*` 清单。IDF 在构建输出中仍可能打印通用刷写提示，直接
执行 flash target 也会重新生成清单；不要照着做。直接运行 `idf.py build`、`idf.py reconfigure`、`idf.py merge-bin` 或任何
flash target 都会绕过 app-only 清理，同样不要用。

刷写时不写 Bootloader、分区表、NVS 和 `assets`，不用 `idf.py flash`、`idf.py app-flash` 或 `@flash_args`：只把 app 写进一个
OTA 槽，再写选中它的 `otadata`。构建可复现（`CONFIG_APP_REPRODUCIBLE_BUILD`）：同一份源码在 ARM 机器上（Mac，或 ARM 版的
`espressif/idf:v6.0.2` 镜像）编出的固件逐字节一致；在 x86 机器上（例如 GitHub 的 CI）编出的，只有固件头里记录的 ELF
哈希和随之变化的两个校验值不同，代码和数据相同。
[`scripts/boilon/local_ci.sh`](../../../scripts/boilon/local_ci.sh) 在本机的 Docker 里照 CI 的步骤跑一遍。
